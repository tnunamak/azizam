P1 — Try: typing changes the focused element
web/src/app/try/workflow-inputs.tsx:327–349.
“As a keyboard user, I enter a longer prompt and the field is replaced while I am typing.” The length-over-80 branch switches Input to Textarea, unmounting the active element; source indicates focus/caret loss risk at that boundary. This makes a simple household task feel unreliable.
Change: render one Textarea for free-text strings from the outset; resize its height without replacing the DOM node. Preserve value, focus and selection. Verify typing/pasting/deleting across 80 characters. Relevant criteria: 2.1.1 Keyboard, 2.4.3 Focus Order.

P2 — Add engine: the Preset's local error is disconnected
web/src/components/admin/add-service-dialog.tsx:250–276; web/src/components/ui/field.tsx:43–65; web/src/components/ui/select.tsx:27–50.
“As a screen-reader user, I hear 'Fix the highlighted fields' but the Preset control does not tell me its specific error.” Field supplies context, but this direct SelectTrigger neither consumes it nor receives its generated id, description or invalid state. The explicit 'Preset' name prevents an unnamed control, but does not connect its guidance. Setup should explain precisely what needs fixing.
Change: have SelectTrigger consume Field context, merging id, aria-describedby and aria-invalid with explicit props. Associate “Select an available engine preset.” and the preset guidance with the trigger. Keep the focused error summary, and make its field names links to the invalid controls. Criteria: 1.3.1 Info and Relationships, 3.3.1 Error Identification, 3.3.2 Labels or Instructions.

P2 — Shared Combobox: error feedback is not announced or associated
web/src/components/ui/combobox.tsx:52–60,107.
“As a screen-reader user, I learn this selection is invalid, but must search surrounding content to discover why.” The error paragraph has no id or live-region role; aria-invalid alone cannot provide its text. That unnecessary search conflicts with calm, explainable recovery.
Change: render a persistent error container with id derived from useId and aria-live="polite"; reference it using aria-describedby on the trigger. Put the existing error text there, and announce loading completion once without moving focus. Criteria: 1.3.1, 3.3.1, 4.1.3 Status Messages.

P2 — Usage: visible section titles are absent from heading navigation
web/src/app/usage/page.tsx:461–466; web/src/components/ui/card.tsx:30–37.
“As a screen-reader user, I cannot jump to 'Requests by day' using headings, although it looks like a section title.” CardTitle renders a div. The monthly summary should let everyone skip directly to the detail they need.
Change: give CardTitle an explicit semantic-element option; render “Requests by day” as h2 under the page h1. Retain non-heading markup for metric values such as a currency amount; do not globally turn every CardTitle into h2. Criteria: 1.3.1, 2.4.6 Headings and Labels.

P2 — Usage: capability comparison relies on colour for sighted users
web/src/app/usage/page.tsx:508–559.
“As a colour-blind household member, I can read capability names but cannot reliably match their coloured dots to stacked bars.” The full table is sr-only, so it is not a visible alternative. Sharing one colour for audio and voice also makes some segments intrinsically ambiguous. Usage must make cost and activity understandable without decoding a palette.
Change: add a keyboard-operable “View data table” disclosure directly beneath the chart, exposing the existing date/capability/total table to everyone; add distinguishing segment patterns or direct labels. Preserve the screen-reader equivalent. Criterion: 1.4.1 Use of Color; table solution also supports 1.1.1 Non-text Content.

P2 — Add engine: connection-test result is visually updated only
web/src/components/admin/add-service-dialog.tsx:309–330.
“As a screen-reader user, I press Test connection and cannot tell when the inline success or failure arrives.” The returned probe is a plain div/span. A trustworthy operator surface must announce the actual result rather than leave the owner guessing.
Change: keep a mounted role="status", aria-live="polite", aria-atomic="true" result region. Update it to “Testing connection…”, then “Connected. HTTP {status}.” or “Connection failed. {reason}”. Leave focus on the test button; expose the endpoint as ordinary adjacent detail. Criterion: 4.1.3.

P2 — Contrast and focus visibility remain unverified
web/src/app/globals.css:4,32–35; web/src/components/ui/button.tsx:7; web/src/components/ui/input.tsx:10–12; web/src/components/ui/select.tsx:40.
“As a low-vision user, I depend on quiet text and the keyboard focus indicator remaining distinguishable in both themes.” globals.css references externally defined colours; these controls replace the base outline with a 50%-opacity ring. The definition file is excluded by the assignment's path rule, so no contrast ratio or failure can honestly be asserted.
Change: measure computed light/dark text, placeholders, boundaries and focus colours before release; use an opaque tested focus colour if the current composite fails. Require 4.5:1 normal text, 3:1 large text and applicable 3:1 non-text contrast. Criteria: 1.4.3 Contrast (Minimum), 1.4.11 Non-text Contrast, 2.4.7 Focus Visible. This is a verification gap, not a measured violation.

Three delight opportunities
1. Usage: the visible data-table disclosure can include a short factual sentence such as “Most requests were on {date}: {count}.” Generate it from the same dataset; keep it available without hover.
2. Try: stable, auto-growing text fields can announce “Inputs ready” only when a previously invalid form becomes valid, giving a reassuring recovery milestone without narrating every keystroke.
3. Library: after filters settle, announce one concise result such as “12 matching items loaded. More available.” Keep focus in the filter and avoid announcements during each keystroke.
