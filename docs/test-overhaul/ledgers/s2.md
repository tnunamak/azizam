## Ledger conventions

“Same ID” means the exact fully qualified old ID in that row, with any explicitly listed new parameterization, in the same scoped file. Tier names distinguish unit/route contracts, SQLite integration, proxy integration and seeded-scenario integration; they do not assert existing pytest markers.

Every row preserves all existing assertions except the explicitly identified fake-only key-prefix expectation. The mutant column gives named semantic mutation specifications, not source-verified executable diffs. “Both must kill” is the required preservation gate; “old expected survive/new must kill” is a strengthening hypothesis. Every old and new outcome is UNVERIFIED until both green baselines and independent mutation runs exist. Expected messages are proposed explicit assertions, not captured test output.

Store-only faults cannot generally prove preservation of a fake-backed case: pair them with a named route/projection regression that exercises both old and rewritten cases, and retain the old original fixture as a control during the comparison. Do not force or report the requested claim that old tests pass all mutants: a mutant in shared route code can kill old fake-backed tests too, and some proposed mutants do not affect original data at all.
