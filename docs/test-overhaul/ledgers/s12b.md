## Ledger conventions

- Fxx expands to the exact source path in the file manifest below. An old ID is Fxx::the exact test declaration title plus its explicit parameter expression and line locator. Parameter placeholders remain in the title to avoid guessing Vitest pretty-printing; one row is supplied per parameter invocation.
- K = keep body and every existing assertion unchanged. No move/merge/deletion is proposed for K, so mutation proof is not a migration prerequisite for that row. Its title is an identifier, not a claim that every word of the title is asserted.
- R = retain old case ID and all old assertions, augment with the named successor. Original IDs remain traceable. New cases are design names, not files already created.
- SHARED = S12a primary, non-additive. The shared source inventory is complete here; S12a's corresponding full ledger governs implementation.
- U = pure function/boundary unit; C = Vitest component integration using real production components/helpers; B = real browser with production CSS and independent geometry/visibility/hit-test oracle. C+B means keep C wiring/semantics and add B, not replace one with the other. Proposed B home is web/tests/browser/s12b-component-contracts.spec.tsx; its future creation/configuration must be scoped by the implementation owner. Shared B homes belong to S12a instead.
- A named mutant X.P should be killed by old and successor (preservation prediction). X.S should survive the identified old oracle and be killed by the successor (strengthening prediction). P/S are static predictions only, never observed kills. When multiple assertions exist, a mutation proves only the named invariant, not all coverage.
- Failure diagnostics are proposed custom assertion messages or equivalent expected assertion mismatch, not captured runner output.
- Required gate: every old assertion stays until the exact single-site production mutant/red/green successor demonstrates the intended invariant and review approves any later removal. This proposal itself removes none.

## Cross-cutting implementation design

### Harness, mocks and databases

- These are frontend component, pure presentation and HTTP-boundary tests. There is no SQLite repository/store implementation in the scoped files to replace. Inserting SQLite into a DOM test would not address these oracle gaps. Real SQLite/template-database coverage belongs in a separately authorized server integration tier and must use the real server migrations/store; it cannot substitute for these UI state/permission/byte assertions.
- Keep real QueryClient and real components/classifiers where their behavior is the subject. Stub transport/media/clipboard/IntersectionObserver boundaries only. Use strict handlers keyed by exact URL, method, request body and expected scope; unexpected requests fail immediately. Preserve explicit ETag/If-Match and exact payload equality in engine/category examples. Avoid fixtures that return a plausible body for every path.
- Scope fresh clients per render/test; disable automatic retries as existing fixtures do, explicitly cancel queries and clear clients after unmount when implementation tests are authorized. Restore manually redefined prototype properties and clipboard/execCommand descriptors, not merely vi.unstubAllGlobals. Reset spy implementations, mock calls, session caches and storage with explicit ownership. Do not assume an unseen global restoreMocks config.
- Control promise settlement with deferred Responses/mutations inside act. Wait for the relevant DOM transition/effect to settle before asserting an element is absent, especially job acknowledgements. Fetch invocation alone is not failure settlement; getQueryData alone is not UI readiness. MutationObserver zero-change checks must await record delivery, then disconnect in finally.

### Clocks and scheduling

- Use a literal fixed epoch T0 and fixed locale/timezone for age/cutoff assertions; make observed_at and generated_at intentionally different. Freeze Date independently when wall-clock only is used.
- For search debounce and job polling, fake only required timers and supply userEvent's advanceTimers callback; advance exact just-before/at thresholds inside act, flush microtasks/React updates, and assert both call counts and final UI. The actual production debounce, freshness cutoff and notifier age cutoff are UNVERIFIED until production inspection. Do not invent constants from waitFor timeouts.
- Leave Radix focus and user-event scheduling compatible with the chosen timer mode; avoid mixing fake timers with real waitFor sleeps or advancing all infinite recurring poll timers. Unmount, cancel, clear queues and restore timers deterministically. Existing deferred media tests already avoid sleeps; retain that strength.

### Parametrization, property and golden oracles

- Parameterize unsafe registry refresh and malformed provider success bodies as named independent scenarios. Preserve each original assertion and each explicit HTTP/name/role branch. Parameterized status expectations must be literal independently reviewed data; never derive expectations by calling the classifier under test.
- Keep the23 literal token cases as low-level source checks and add a reviewed computed-value golden at16px root. Geometry goldens cover the specific old contracts and are not blanket screenshot updates. A source class or mock prop is wiring evidence only.
- Health aggregation can add deterministic permutations of known rows: faults-only count, worst severity independent of ordering, and exact popover identities. Seeded property-based generation is useful but optional; no new package was installed. Record seed/shrunk counterexample when run.
- Clipboard state can add a tiny independent state-machine oracle: current value-generation and newest attempt own visible state; older settlements cannot overwrite it. Generate resolve/reject ordering, A→B→A, success→failure, and simultaneous attempts. Retain the concrete existing cases even if a generated case passes.
- Waveform oracle uses supplied literal peaks/progress boundaries and independent mathematical expectations. It must not compare output against another call to the production render helper. Any scaling convention not implied by the current tests remains UNVERIFIED pending source/contract inspection.
- Pure category snapshot functions are shared S12a: golden complete snapshots retain provenance, grants, retained bundles and CAS semantics; a round-trip property alone cannot establish correct content because symmetric corruptions can pass.
