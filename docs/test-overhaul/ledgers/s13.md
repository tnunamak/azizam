## Preservation notation

Each ledger row references an invariant I-ID, mutant family M-ID, and expected failure F-ID in the contract table. All columns expand through those definitions; no matrix cells are omitted. A family contains separate single-change mutants for each listed alteration, not one multi-change patch. Parameterized rows apply the corresponding state/theme/width branch only.

P = old case statically predicts failure on that mutant and proposed survivor must also fail; neither has been run. N = oracle strengthening; old case does not reliably catch it. C = conflicting contract; no safe deletion. L = lexical-only preservation; browser equivalence UNVERIFIED. Where a prerequisite currently fails or a test skips, even predicted P is not evidence of a kill. Expected failures are proposed stable assertion messages; actual Playwright/Node errors are UNVERIFIED.

Q means retain the original serious/critical axe-empty assertion and no-horizontal-overflow assertion at their original checkpoint(s), not merely a screenshot. M-Q-a11y introduces a serious/critical violation on that exercised view; M-Q-overflow forces the exercised view wider than the viewport. Expected failure: '[S13/Q] serious/critical violations must be []' or '[S13/Q] document.scrollWidth must be <= viewport width'. H1/H3/H4 additionally retain label-content-name-mismatch independent of severity. Screenshots in these sources are diagnostic captures, not baseline comparisons. No golden oracle is currently established. Reduced-motion emulation alone is not a reduced-motion oracle.
