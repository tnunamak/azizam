## How to read the ledger
Each file section supplies the exact tests/<file>.py prefix. Append :: plus the Old case column to obtain the complete old case ID; unittest classes are included. Bracketed named parameter tuples identify source parameters exactly, not claimed pytest-generated collection IDs. The two identity route values are retained as the source expressions because their constant definitions are outside scope. Every row's new home SAME means the identical file, class, function, and parameter tuple shown in that row; preserve those cases while changing only the setup/clock/race machinery described below. U = isolated unit test, I = real-store/route integration test. This design deliberately avoids unproven case deletion or case consolidation; shared setup does not mean shared mutable state.

The invariant column is the behavior that must survive, including multiple assertions within one method and non-subTest loops. Explicit subTest rows retain their listed key. Expected failure messages are proposed diagnostic labels to add to the rewritten assertion groups, not observed output; existing pytest/unittest assertion text will otherwise differ. For a given row, its exact proposed message is the Failure column followed by ': ' and its Invariant column. Parameter values in the failing node identify which instance failed.

M1-M6 are the six requested semantic mutant requirements defined below. U0 means production target and mutant/revert are UNVERIFIED for this retained contract, not a fabricated mutation. Every old/new kill claim is UNVERIFIED, including where static assertions plausibly cover a mutant. P? means a candidate preservation check (both old/new must fail); S? means added oracle strengthening (only new is expected to fail), not proven kills. New tests listed separately have no deleted old case.

## Risks and nonclaims
- DD11/DD12 and section2.2 pair membership are undefined in the allowed sources: no deletions or five-pair mapping justified.
- The session_make_runtime canceled-queued test and omitted prompt-memory files cannot be read; their proposed replacement, 17.9s claim, and flaky sleep inventory remain UNVERIFIED.
- Only two asyncio.sleep(0) scheduler yields were found in the allowed test bodies; no positive-duration sleep or timed thread join was found. The string b''.join in privacy scans is byte concatenation, not a thread join.
- A one-transaction seed does not remove recovery's own transactions. The 61s/410-commit claim and 200-280 test-second savings are unmeasured. Turning durability off can hide precisely the recovery behavior this slice protects.
- Template copies must be made only after connections close and WAL is checkpointed; copying a live .db without WAL/SHM is unsafe. Avoid global initialization caches keyed by old paths and mutable session fixtures.
- Source-visible constants in audience tests and ALL_STATUSES can make self-confirming oracles. Preserve current cases and add independent expected sets; do not silently replace dynamic exhaustive loops with fewer hardcoded values.
- canary byte scans are stronger than row absence but cover only opened roots/files and exact encoding; cover UTF-8/unicode, metadata decoding, DB/WAL/cache/receipt surfaces as applicable. Do not claim all possible transformations or memory erasure.
- Fixed wall-clock values alone do not force scheduling order; Events alone do not define cutoff equality. Use both. Timeouts remain finite deadlock guards.
- Existing backend doubles and dictionaries are not evidence of real service behavior, physical durability, disk erasure, or process-crash recovery. Reopening a database is a durable-smoke boundary, not a forced power-loss test.
- Some new seams and fixture factories cannot be resolved without production/imported fixture reads. They are design requirements, not verified callable APIs.
