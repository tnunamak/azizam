## Test tiers and preservation convention
U = pure/helper unit; C = offline gateway contract (real gateway routes, serializer, normalization and policy; scripted external transport only); SDK = C decoded by an explicitly pinned real SDK; DOM = complete-app bounded DOM/fetch behavior; L = separately selected scheduled live probe. Scheduling is a plan label, not an automation created here. Running any actual billable/model probe remains outside this assignment.

All old assertions, request options, successful/error paths and parameter values listed below are contractual minima, not replaced by weaker golden summaries. SDK requests must traverse the genuine gateway serializer; hand-authored final responses are insufficient. A deterministic upstream fixture is permitted; a fake gateway serializer or fake persistent store is not.

P* = candidate preservation mutant: static reading predicts old and new tests kill it only under a fixture/SDK path exercising the stated assertion. No kill was executed or verified; skipped old live probes provide no evidence. S = oracle strengthening: old case can survive, new case must fail. Each S addition retains a distinct P candidate/old assertion. A fixture or SDK negative control is explicitly not a gateway production mutation. Expected failure strings below are prescribed diagnostics for rewritten tests, not claimed observed output.

Proposed exact new case identifiers use the old file::class::method (or Node test title), suffixed [mode=contract,sdk=<exact-pin>] for SDK routes, [mode=contract] for raw/gateway/DOM, or [mode=surface,sdk=<exact-pin>] for resource checks. Existing live variants keep the same case id with [mode=scheduled-live]. Exact-pin is a required matrix variable, not an invented installed version. IDs are proposed test-design names; no files have been changed.
