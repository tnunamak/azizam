## Ledger conventions
Every old case ID below is web/e2e/<file>.spec.ts::<exact expanded test title>. L is the current declaration line, solely an anchor. Each expanded parameter tuple is separately listed. No case is deleted without a named survivor.
F = browser functional contract tier; R = browser + real fixture backend tier; G = browser geometry/accessibility/golden tier. Proposed new cases stay in the original file unless stated otherwise. New case suffixes are literal proposed IDs.
For matrix rows, new functional ID is <file>::<family> functional <semantic key>. Geometry ID is <file>::<exact old title> [geometry]. Functional keys retain route, surface, state and count; theme and width are removed only from repeated functional actions. Width-dependent controls remain exercised in G (for example Library phone Search). E-apply F is R tier, not a route mock.
Each G survivor retains all original overflow, target geometry, readiness, serious/critical axe checks and relevant UI state checkpoints at the SAME original theme, width and state. Its screenshot becomes an assertion. It is not merely an initial-page snapshot.
P = static expectation that both old and new assertion sets kill the named mutant; S = strengthening, old case has no sufficient oracle. Both statuses are predictions, never executed kill evidence. M-G and M-A are P where the original has those checks; M-T is S for a contrast-preserving incorrect token because existing screenshots are only saved.
Expected messages are proposed assertion labels and expected diffs, not observed Playwright logs.
Unchanged rows keep their complete existing bodies and tier; no deletion or mutation proof is inferred from their names.

## Deterministic race and multipart design
Provider race:
- Before the first click, create 'request entered' and 'response released/completed' promises in the test route; wait until first request body is captured before navigating Back and selecting provider B.
- Hold A response, select B, verify key empty and controls disabled, arm requestfinished/response.finished or a deliberately observed requestfailed branch, then release A.
- Wait for transport completion AND a UI-processing barrier (verified application pending-state/handler signal, or component-level deferred API promise followed by framework act). requestfinished by itself is not proof React finished applying the response. If no observable UI barrier exists, retain as UNVERIFIED; do not replace sleep with another arbitrary timer, a lone negative assertion, or only clock.fastForward100.
- After settlement, A result and models absent, B credentials empty, Check and Next disabled. Submit B, assert B result and model, exactly two correctly paired provider/body entries. Test stale-success mutation; optionally stale-failure separately.
Multipart:
- Parse boundary from actual Content-Type, parse binary parts with a standards-compatible parser, reject malformed boundaries and duplicate names, compare canonical field multimap.
- Exact fields: prompt='Turn this source into a crisp launch clip.', mode='product', frames='18', strength='0.65', preserve_detail='false', colorGrade='teal'. Exact file field source, filename clip.mp4, MIME video/mp4, bytes equal uploaded Buffer.from('fake mp4'). Include allowed fixture-generated fields only after inspecting real contract; no permissive contains fallback.
- Before file selection assert zero intercepted submission count AND inline 'Choose a video first', one picker/no example-path text. After file selection exactly one POST to declared gateway path and rendered image. Curl independently preserves file/prompt/colorGrade and no erroneous /openai/v1/gateway prefix.
Ready/idle:
- Existing composed fixture has inputs but no example_request and native_route:null. Amend test-owned catalog with a valid explicit request declaration (method/path/content type/body) matching approved contract once production is readable; do not guess a live endpoint.
- Assert empty prompt, fill it, arm exact route capture, click Run, assert one complete JSON request and deterministic result. Retain ready no-note and idle Ready to start/reason/no Unavailable. Until request contract verified these are design-only S cases.

## Risks and limits
- Read-scope conflict prevents source-backed exact production diffs. Exact fixtures, API schema, polling timers, SQLite implementation and config/project test collection remain UNVERIFIED.
- 394 is static expansion of these26 files only. Existing test.use, project filters, dependencies, retries or feature flags could change collected count. No measured reduction/time estimate is trustworthy here.
- Full tuple parity is intentionally retained. Compressing test declarations or moving assertions does not itself reduce checks or prove90 seconds saved. A later small matrix can lose a single-page dark-desktop bug, error-only overflow or modal-specific axe failure.
- All file-output screenshots currently lack comparison at cited sites. Golden tests strengthen oracle; existing saved screenshots cannot be credited with catching contrast-preserving wrong token.
- Source line locations are pinned SHA only; do not apply against HEAD without re-reading authorized files.
- Template clones must include real policy/auth/category/media state and schema. UI route stubs cannot verify backend revocation, signed URL security, paid access enforcement or ETag rejection.
- Shared shard mutable globals: categories active revision, engine registry substrate, fixed capture-engine, OpenRouter removal/recreation, Home profile mapping and fixed real-member email can contaminate other files. Fail-fast isolated teardown is preferable to .catch-ignore cleanup.
- Provider cleanup settles pending charges at zero in test fixtures. Never run it against a user's live backend. This assignment did not run any request-producing test.
- Contract traps: subset assertions toMatchObject and flags can admit extra fields; truthy ETag is not correct ETag; expected values produced by production chatAlias can share defects; validation test title mentions enum without testing it; 'real admin paths' test uses mocked routes.
- Stale provider transport completion is not React state completion. A clock-only or negative-before-settlement rewrite can turn a flaky test into a false positive.
- Existing composed ready/idle cases lack runnable metadata. Blindly adding click Run would exercise missing-example validation rather than availability execution.
- Async workflow failure test also overrides old job poll URL, masking possible stale job identity. Keep existing behavior, and add exact latest job-id poll/no-old-request oracle as S in a later scoped rewrite.
- Third-party/example media URLs should remain controlled test data. Binary bytes must be checked as bytes; invalid fake audio/video proves element rendering, not playback. Keep actual WAV/video decoder tests separate.
- Personal absolute screenshot/mkdir paths and collisions across files break portability/evidence ownership. Stable golden IDs must include file, state, theme,width,checkpoint without secrets.
- Date.now fixtures created at module load and browser clock at runtime can disagree. Share one test constant for UI fixture times, keep server/auth clock independent unless explicitly supported; unique names need deterministic per-test identifiers rather than wall clock only.
- Permission/security/billing changes, publication, deployment, Work/Codex tasks and paid model calls are not part of this read-only deliverable.
