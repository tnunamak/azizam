## Risks and acceptance gate
1. Scope mismatch is the primary blocker to full S9 acceptance: missing named tests, production lines, artifact inventory, deletion mapping and 57-case manifest. This report must not be labeled a complete full-slice preservation ledger.
2. Per-artifact graph regressions cannot be replaced by a schema-only mapping test or an empty glob. Test-owned expected destinations and independent canonical goldens are essential.
3. Goldens built from the current converter can canonize the defect; review original committed source separately and preserve semantic edge/output-index distinctions. Avoid over-normalizing list order and numeric/string differences.
4. Shared mutable graph fixtures and import-time TEMPLATE/FACES data can cross-contaminate tests. Deep copies and isolated data are required whenever the ledgered case is rewritten.
5. Broad fake-store elimination here would touch paid billing/auth/secret behavior with APIs unavailable in scope. Real SQLite already exists in many provider cases; replacing all doubles indiscriminately would remove useful failure injection and external isolation.
6. Static registry/source guards do not establish functional registration; constructor tests alone also bypass registration. Keep both kinds.
7. Missing explicit artifact IDs leaves parameter preservation incomplete even when declaration totals match. Require exact enumeration before implementing dynamic-loop rewrites.
8. No timing, runtime pass, deployed behavior or mutant kill was verified. Code-reading evidence supports the assertions described, not operational correctness.
