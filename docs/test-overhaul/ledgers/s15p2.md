## Ledger conventions
P = preservation candidate: static reading predicts both old and rewritten case fail on the named mutant. S = stronger oracle: the described old assertion misses that specific fault, and the new assertion is intended to catch it. Every kill prediction is UNVERIFIED until measured; "P" does not mean a recorded kill.

Parameter suffixes show exact semantic values from source, not purported pytest-generated collection IDs (module/lambda parameter auto-IDs were not collected). Suffixes for unittest subtests and ordinary loops identify logical branches of that original method. The complete old case identity is file::class::method[values] or file::function[values]. New home "same ID" means exactly that complete old identity, with each existing parameter/branch preserved; tier is specified per row. For logical loop branches, keep that branch in the same method unless later parameterized with an explicit node mapping. Expected failure text is proposed diagnostic text for the rewrite, not a claim about exact current pytest output. Retain existing exception type/message assertions in addition to these diagnostics.
