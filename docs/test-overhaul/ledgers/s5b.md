## Concrete implementation recipes (design only)

### 1. Method-local UTC time, preserving real storage

At this SHA the specifically named methods start at M:331 and M:797; the additional previous-month fallback case starts at M:637. Freeze these methods only. Use a fixed aware UTC instant (2026-10-15T12:00:00+00:00), and the corresponding integer epoch for every seeded receipt/job/cache timestamp involved. Patch the datetime lookup used by me_media for the entire seed-and-request interval; the existing M:1128-1129 test demonstrates patch.object(me_media, 'datetime', wraps=datetime) with clock.now.return_value. Capture the real datetime class and epoch before patching. Where a store obtains time.time internally, use a tightly bounded time patch or explicit created_at/now argument already exposed in these tests. Do not freeze monotonic clocks used for thread watchdogs. Avoid a global setUp freeze: it would also change the 79 retained methods, including deliberate multi-month retention scenarios.

Preserve the child receipt/job linkage, all six failure statuses, the 55-success overflow, the 50-row presentation cap and the previous-month fallback. Parameterize NEW boundary coverage over October, January year rollover and leap-March 2028: timestamp=start-1 excluded, start included, and start+1 included. Include a current-month control alongside last-month fallback so an implementation returning no media cannot pass. A fixed clock fixes nondeterminism; these new boundary examples strengthen coverage. Do not claim the existing last-month-only case kills a next-month-start mutation: both can incorrectly return zero. No upper-bound/future receipt exclusion contract was established by these tests; do not invent it.

The current SQLite tests already exercise admin_store, media_jobs, receipt_store and prompt_memory using actual files. A template database can be considered only AFTER profiling proves schema initialization dominates: initialize via real migrations, close all connections, checkpoint WAL, use SQLite backup into independent per-test paths, then create per-case users/apps/credentials through real APIs. Never share mutable DBs between tests or copy only a live .db while ignoring WAL. Fresh-schema, upgrade, retention and index-plan tests must continue constructing their actual migration starting states. This proposal does not introduce a template or rewrite shared fixtures; doing so would require preservation rows for every affected declaration before acceptance.
