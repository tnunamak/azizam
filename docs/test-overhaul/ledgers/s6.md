## Ledger conventions
P = preservation: old and proposed case are expected to fail on the named mutation when the old path is exercised. S = strengthening: existing test demonstrably skips, returns early, or lacks the new oracle. These are static expectations, NOT executed kill claims; every red/green result remains UNVERIFIED.
T0 = pure or event-driven unit test with transport doubles; T1 = offline app/store integration with real SQLite where persistence matters; T2 = real-socket or codec integration.
All existing cases below have no pytest parameter decorators; the original no-parameter identity is explicit. Cases keep their IDs and every old assertion unless the new-home column names the one intentional EOF-test rename. Proposed assertion messages are stable future test diagnostics, not observed failure output.

Do not remove legitimate environment gates in unrelated real-socket suites.

Existing stream cases already use this explicit name. Keep their stream=True checks, original delta bytes and final-event checks.
3. Use one disposable receipts.db per test via receipt_store.init_db, which this file already calls. For durable-success and no-body-leak cases, wrap the real receipt_store.record solely to force the isolated path and record invocation count; do not return a synthetic success. Do not count a spy's in-memory serialization as persistence. All active DB paths and metrics sinks must be isolated before calling proxy functions. 4. Keep request_id equality and top-level prohibited-key assertions. 5. In persistence-failure case, count the failing write hook's invocation (exactly once), inject RuntimeError("disk full"), and retain no-exception plus receipt.status=="ok". A hook that never runs must fail. Do not replace this necessary fault-injection seam with a fake whole store.
