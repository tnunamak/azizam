## Preservation policy and legend
U = deterministic unit/data transformation; C = offline route/contract with real gateway code, real temporary persistence where used, and network intercepted only at the external transport; SDK = independently pinned offline SDK environment. No scoped case is moved into a live/scheduled tier.
P means old and proposed cases are predicted to kill the specified mutation; S means the new oracle is predicted to kill a mutation that the old oracle misses. These are static predictions, NOT measured kills: every old/new mutant result remains UNVERIFIED. Mixed rows distinguish P and S.
Every existing assertion and input variant remains unless the ledger expressly strengthens its oracle; fixture rewrites must not reduce schema, auth, transport, error, state, ordering, content or timing coverage. No deletion is authorized by this plan.
Expected failure messages are proposed diagnostic assertions to implement, not observed pytest output. Each is to be prefixed with its exact case id and mutation id. Normal KeyError/schema-validator failures also count only after confirming the mutated line was executed.
Where one old unittest method contains several sequential checkpoints, the ledger uses descriptive [parameters] to make them auditable; these are documented source subcases, not a claim that pytest already collects separately named ids.
