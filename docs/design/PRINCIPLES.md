# Azizam design principles (draft, adopted for Phase B; revisit at T1)

Each principle comes from the owner's own words, quoted verbatim with its date. Each has a check, so it can be tested on a screenshot.

| # | Principle | Owner's words | Check on a screenshot |
|---|---|---|---|
| P1 | Every element pays for its attention. | "everything in the design that requires cognitive processing carries a cost" (2026-06-04) | For each element: what decision does it change? Remove it if none. |
| P2 | One fact, one place. | "iI spent two seconds looking at the ui: this burns my attention by being repetitive" (2026-10-04) | No repeated fact or sentence on a screen (lint plus a two-second look). |
| P3 | A failure names its layer and the next action. | "it's not clear if there is a gateway problem or a user problem or a model problem or workflow problem ... users shouldn't have this kind of trouble" (2026-10-02) | Every error state names the layer (or says it is unknown) and one action. |
| P4 | A family member understands it without help, on a phone. | "an experience my wife can understand and find delightful" (2026-06-14); "family members ... not a toy" (2026-10-03) | Member journeys pass at 390 px without help; no glossary-banned words. |
| P5 | Complexity is navigable, not scary. | "a lot of complexity we need to make navigable and not scary and easy" (2026-10-03) | The first viewport answers the surface's one question; detail is one step away. |
| P6 | No marketing voice inside the product. | "we shouldn't have a big slogan like 'Build on AI in minutes'" (2026-06-25) | No slogans or hype adjectives in product surfaces. |
| P7 | Honest data, rich wherever real data supports it. | "preserve the newer screenshots' contrast, density, hierarchy, charts-as-visual-pattern, and component language whenever real data supports them" (2026-07-16) | Charts, sparklines and KPI bands are allowed and encouraged on real data; nothing invented. |
| P8 | Members are ordinary users; admins are users with an extra view. | "admins are users too right? don't apps usually have an admin nav from the normal user page" (2026-05-18) | The member shell is the base; owner tools are an added section, not a different product. |
| P9 | Operators find it delightful too. | "r/selfhosted operators should find it delightful to use, too" (2026-05-17) | Each hero surface has one memorable element and one earned moment. |
| P10 | Grounded in real references, not training data. | "pick some direction and then go find a bunch of references and ground the AI to those versus what's in its training data" (2026-08) | Every design change cites a reference id, a token, a principle or a ban-list rule. |
